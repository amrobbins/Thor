# Thor API stub snapshots

This directory is an input to the documentation build, not user-facing documentation.

Thor's native Python signatures are generated by nanobind during a normal Thor Python build. A source-tree CMake build automatically synchronizes those generated `.pyi` files into the PEP 561-style `thor-stubs` package here and regenerates the Python API reference, so the CUDA-free documentation build can consume the exact native API metadata later.

The synchronization is controlled by `THOR_PYTHON_SYNC_DOC_STUBS`. It defaults to `ON` for normal source-tree builds when `tools/docs/sync_api_stubs.py` is available and to `OFF` for isolated scikit-build wheel builds, which must never mutate the source checkout. Wheel builds still generate and install the same stubs into the wheel.

Files under `thor-stubs/` are generated metadata. Do not hand-edit them. The `thor_docs_api_stub_snapshot_check` CMake target verifies both the checked-in snapshot and the generated API-reference Markdown against the current native build.
